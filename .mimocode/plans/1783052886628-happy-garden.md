# Plan: Mandatory API Key Enforcement + Internal Website Key

## Goal
Make `/api/github` require an `x-api-key` header. Block requests without one (401). Add a special internal API key for the website itself, manageable from the admin panel.

## Current State
- `/api/github` — API key optional (line 61: `if (apiKey)`), unauthenticated requests still work
- `/api/track` — Fully public, no auth (analytics tracking from portfolio site)
- `/api/auth/github` — Public (OAuth callback, must stay public)
- `/api/keys` — Session-cookie auth (manages keys, not consuming API)
- No shared auth middleware — each route does inline checks
- `site_settings` table stores key-value config (existing `get_site_setting`/`update_site_setting` RPCs)
- `PublicAnalytics.tsx` calls `/api/github` **without any key** — will break when we enforce

## Architecture

### Key hierarchy
1. **Site API key** — stored in `site_settings` as `site_api_key` (plaintext). Website uses this for self-calls. Admin manages via panel. Bypasses rate limiting.
2. **User API keys** — existing system. Users create keys via dashboard, validated via `validate_api_key` RPC. Rate limited.

### Validation flow
```
Request → middleware.ts (check header exists) → route handler (validate key)
```

- Middleware: fast check — blocks missing `x-api-key` (except `/api/auth/*`, `/api/track`, and OPTIONS)
- Route handler: full validation — check against site key or hash against user keys

### Step 3: Add site API key RPC functions
**File:** `database.sql` (append)

```sql
-- Get site API key (admin only)
create or replace function public.get_site_api_key(p_token text)
returns json language plpgsql security definer as $$
declare v_admin_id uuid; v_key text; begin
  v_admin_id := public.verify_admin_internal(p_token);
  select value into v_key from site_settings where key = 'site_api_key';
  return json_build_object('key', v_key);
end; $$;

-- Regenerate site API key (admin only)
create or replace function public.regenerate_site_api_key(p_token text)
returns json language plpgsql security definer as $$
declare v_admin_id uuid; v_key text; begin
  v_admin_id := public.verify_admin_internal(p_token);
  v_key := 'rv_site_' || encode(gen_random_bytes(24), 'hex');
  insert into site_settings (key, value, updated_at) values ('site_api_key', v_key, now())
    on conflict (key) do update set value = excluded.value, updated_at = now();
  return json_build_object('key', v_key);
end; $$;

grant execute on function public.get_site_api_key(text) to anon;
grant execute on function public.regenerate_site_api_key(text) to anon;
```

### Step 4: Add auth.ts client functions
**File:** `src/lib/auth.ts`

```typescript
export async function getSiteApiKey(): Promise<string | null> {
  const token = getStoredToken();
  if (!token) return null;
  const { data, error } = await (await getSupabase()).rpc('get_site_api_key', { p_token: token });
  if (error || data?.error) return null;
  return data?.key || null;
}

export async function regenerateSiteApiKey(): Promise<{ key?: string; error?: string }> {
  const token = getStoredToken();
  if (!token) return { error: 'Not authenticated' };
  const { data, error } = await (await getSupabase()).rpc('regenerate_site_api_key', { p_token: token });
  if (error) return { error: error.message };
  if (data?.error) return { error: data.error };
  return { key: data.key };
}
```

### Step 6: Frontend — use site API key for internal calls
**File:** `src/components/shared/PublicAnalytics.tsx`

Update `fetchGitHub` to include the site API key:

```typescript
let _siteKeyCache: string | null = null;

async function fetchGitHub(path: string): Promise<any> {
  if (_siteKeyCache === null) {
    const { getSiteApiKey } = await import('@/lib/auth');
    _siteKeyCache = await getSiteApiKey() || '';
  }
  const res = await fetch(`/api/github?path=${encodeURIComponent(path)}`, {
    headers: _siteKeyCache ? { 'x-api-key': _siteKeyCache } : {}
  });
  return res.json();
}
```

Note: `getSiteApiKey()` requires auth token (admin session). For public visitors, the GitHub stats section will show an error if no admin has logged in to set the key. This is acceptable — the admin must configure it first.

**Alternative (simpler)**: Store the site API key in localStorage when admin copies it, and read from there. This avoids the auth dependency for public visitors.
